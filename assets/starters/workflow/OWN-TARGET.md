# Own-target workflow (stateful tool lifecycle)

This directory is generated by `init --starter workflow` (alias `stateful`).
It is a synthetic refund fixture, not a payment integration.

Response-only JSON chat is the other supported pattern (`--starter
response-quality`). Streaming, WebSocket, history-array multi-turn, and
connector marketplaces are not supported.

This 0.3.4 package generates these files and includes `probe`. Do not pin
immutable npm `0.3.3`. If you built this repository, substitute
`node dist/index.js` for `augmentworks` below.

## Files

| File | Role |
| --- | --- |
| `augmentworks.yaml` | prepare / send / observe / cleanup. |
| `augmentworks.assessment.yaml` | Hosted `support-refunds@0.2.0` assessment. |
| `references/refund-policy.md` | Synthetic policy facts. |
| `fixtures/` | Offline mapping-preview JSON. |
| `server.mjs` | In-memory lifecycle, controlled tool failure, cleanup. |

The fixture server:

- `POST /__augmentworks/prepare` stores one packet-provided order.
- `POST /chat` refunds an eligible order, denies an ineligible one, leaves
  shipping questions unchanged, acknowledges `[aw-connection-probe]`, and
  emits a failed `refund_order` tool result for `[aw-tool-failure]` without
  changing observed state.
- `POST /__augmentworks/observe` returns allowlisted order fields.
- `POST /__augmentworks/cleanup` deletes the fixture and is safe to repeat.

## Commands

```bash
cp .env.example .env
# Set CHATBOT_API_KEY locally. Never commit .env.

node --env-file=.env server.mjs

augmentworks doctor -c augmentworks.yaml
augmentworks preview-mapping -c augmentworks.yaml --operation send --fixture ./fixtures/send-response.json
augmentworks preview-mapping -c augmentworks.yaml --operation observe --fixture ./fixtures/observe-response.json
augmentworks probe -c augmentworks.yaml
augmentworks probe -c augmentworks.yaml --yes
augmentworks test --local -c augmentworks.yaml --packet support-refunds-starter@0.1.0
augmentworks test --assessment ./augmentworks.assessment.yaml --estimate
```

`doctor` and `init` never probe. `probe --yes` always attempts cleanup after
prepare. Hosted `test` needs `--max-credits N --yes`. npm `--yes` is not a
spending ceiling.

Inspect a hosted result with `run status` / `run wait` / `run report` on the
original run. Re-run cleanup by repeating `probe --yes` or stopping the
fixture process. A hard process kill can skip cleanup; real targets need a
server-side fixture TTL.
